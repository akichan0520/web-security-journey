# 第06章：CSS・レイアウト・レスポンシブ

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** 基礎

## この章でできるようになる
セレクタ、ボックスモデル、Flex/Grid、メディアクエリ、フォーカス装飾を使える。

## 全体像
CSSはHTMLの意味を壊さずに見た目を整える。PCとスマホの両方に合わせる。

## 🎙 読み上げ可能な講師ナレーション
CSSは色を付けるだけではありません。余白、幅、文字の読みやすさに大きく関わります。今回の教材画面はカード・グリッド・狭い画面用レイアウトを使っています。デザインは強調するポイントを絞り、見やすさを優先しましょう。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```css
button { outline: none; }
.card { width: 900px; }
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```css
button:focus-visible { outline: 3px solid #1660cc; }
.card { width: min(100%, 900px); }
.grid { display: grid; grid-template-columns:
  repeat(auto-fit, minmax(min(260px, 100%), 1fr)); }
```

## 3. 一行ずつ意味を説明する
1. width:min(100%, 900px) は要素が親幅を越えない設計。
2. focus-visibleはキーボードフォーカスの視認性を保つ。
3. CSSで隠すだけではデータ保護や権限判定にならない。

## 4. 頭の中で処理の流れを追う
① ビューポート幅を想定→② 可変幅を計算→③ フォーカス可視性を確保。

### 根本原因
操作位置が分からず、重要な入力ミスを誘発する。

### 修正の原理
固定幅は狭い画面で横にはみ出しやすい。フォーカスの消去はキーボード利用者に不親切。CSSは表示のための仕組みであり認可の仕組みではない。

### 防御を重ねるとしたら
focus-visibleを残し、コントラストと最小表示幅を確認する。
