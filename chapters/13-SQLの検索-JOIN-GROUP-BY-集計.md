# 第13章：SQLの検索・JOIN・GROUP BY・集計

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** 中級

## この章でできるようになる
SELECT、WHERE、ORDER BY、JOIN、GROUP BY、HAVINGの用途を説明する。

## 全体像
SQLは集合を操作する言語。JOINで別テーブルを関連付け、GROUP BYで集計する。

## 🎙 読み上げ可能な講師ナレーション
1件のデータを取得するだけでなく、複数テーブルをつなげると業務データになります。今回のusersとnotesをJOINすれば、誰が何件のメモを持つかを数えられます。ただし集計時にも公開範囲や権限の境界を守りましょう。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```sql
-- 閲覧者のユーザーIDを条件に含めない
SELECT u.username, n.title
FROM users u JOIN notes n ON n.owner_id = u.id;
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```sql
-- サーバーの認証情報でスコープを固定する
SELECT u.username, n.title
FROM users u
JOIN notes n ON n.owner_id = u.id
WHERE n.owner_id = :current_user_id;
```

## 3. 一行ずつ意味を説明する
1. JOINのONは関連づけを表す。
2. WHEREは結果を現在の利用者に制限する。
3. パラメーターにはサーバーの認証済み利用者IDを束縛する。

## 4. 頭の中で処理の流れを追う
① JOINで関連付け→② WHEREで対象範囲を限定→③ DBが行集合を返す。

### 根本原因
テーブル結合はデータを増やすため、出力条件と認可条件を別に考える必要がある。

### 修正の原理
JOINはテーブルの関係を扱うだけ。SQLの結果セットの範囲はWHEREや権限設計で決まる。画面で非表示にしても取得済みデータの漏えいは防げない。

### 防御を重ねるとしたら
個人データを扱うクエリにはサーバーで決めたuser_idを使う。
