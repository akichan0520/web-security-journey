# 第01章：この教材の読み方・Webの役割分担

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** 入門

## この章でできるようになる
ブラウザ、HTML、CSS、JavaScript、PHP、DBの責任範囲と、コードを読むだけで学ぶ方法を説明できる。

## 全体像
GitHubはソースの保管・レビュー場所。GitHub Pagesは教材HTMLを配信し、PHPは別のローカルサーバーで実行される。

## 🎙 読み上げ可能な講師ナレーション
この講座で実機に脆弱性を再現する必要はありません。サンプルコードはすべて文書として読み、入力から出力までを頭の中で追います。HTMLは文書、CSSは見た目、JavaScriptはブラウザ処理、PHPはサーバー側、データベースは保存と検索です。まずはそれぞれの役割と境界を把握しましょう。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```text
GitHub Pages = PHPが実行できると誤解し、
公開フォルダに秘密の設定値を入れる。
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```text
# 掲載するのは読み物のみ
# docs/index.html : 静的学習ビューア
# chapters/*.md : 比較教材
# .env / 秘密鍵 / 実行用API : 置かない
```

## 3. 一行ずつ意味を説明する
1. GitHub Pagesは静的ファイルを配信する。PHPのソースはここでは実行されない。
2. 公開したリポジトリ内の秘密情報は閲覧可能になるため、教材は架空の値だけにする。

## 4. 頭の中で処理の流れを追う
① 公開されるものを確認→② 端末での実行有無を分類→③ 秘密の情報がないかレビュー。

### 根本原因
0.0.0.0 は全ネットワークインターフェースで待ち受ける指定だから。

### 修正の原理
GitHubでソースを公開することと、サーバーでコードを動かすことは別物。公開されるファイルの中身を先に考える。

### 防御を重ねるとしたら
Docker公開ポートは127.0.0.1に固定。脆弱なAPIは環境変数で別途オプトイン。
