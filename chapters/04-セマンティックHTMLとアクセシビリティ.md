## この章でできるようになる

## 全体像
アクセシビリティは特殊な追加機能ではなく、UIを正しく表現する基本設計。

## 🎙 読み上げ可能な講師ナレーション
色や装飾だけで意味を伝えないようにしましょう。入力欄はlabelと関連付けます。ボタンには理解できる名前を付けます。フォーカスを消してしまうと、マウスを使えない人は困ります。セキュリティ警告も色だけではなく文字で示します。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```html
<input placeholder="メールアドレス">
<div onclick="send()">送信</div>
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```html
<label for="email">メールアドレス</label>
<input id="email" name="email" type="email" required>
<button type="submit">送信</button>
```

## 3. 一行ずつ意味を説明する
1. labelのfor属性とinputのidが対応することで入力欄の名前を提供する。
2. type=emailは入力支援であり、送信値の真偽を保証しない。
3. buttonはEnter/Spaceによる操作や意味付けに有利。

## 4. 頭の中で処理の流れを追う
① labelとidを結び付ける→② type=emailで入力支援→③ requiredは補助→④ サーバー側でも検証。

### 根本原因
入力すると案内が消え、スクリーンリーダーが関係を適切に読み取れない場合がある。

### 修正の原理
placeholderは消えるヒントであり、labelではない。buttonはキーボード操作に対応し、フォームの意味も持つ。

### 防御を重ねるとしたら
label for と input id を一致させ、statusメッセージにはaria-liveを適切に使う。
