# 第16章：認証・パスワード・セッション固定対策

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** 中級

## この章でできるようになる
認証と認可、password_hash/verify、セッション固定、ログアウトの仕組みを説明できる。

## 全体像
認証は「誰か」、認可は「何を許されるか」。ログインが成功しても全データを見てよいわけではない。

## 🎙 読み上げ可能な講師ナレーション
ログイン処理ではパスワードを平文保存せず、遅い一方向ハッシュを使います。PHPにはpassword_hashとpassword_verifyがあります。ログインが成功したらセッションIDを再生成して固定化リスクを下げましょう。多要素認証やレート制限など、本番に必要な仕組みはこの小さな演習アプリとは別に考えます。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```php
// 危険：パスワードを平文で照合・保存
if ($plainPassword === $row['password']) {
    $_SESSION['user_id'] = $row['id'];
}
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```php
// 認証情報は専用ハッシュで保存
$hash = password_hash($password, PASSWORD_DEFAULT);
// ログイン時の照合
if (password_verify($submittedPassword, $storedHash)) {
    session_regenerate_id(true);
    $_SESSION['user_id'] = $userId;
}
// 本番ではレート制限・MFA等も検討
```

## 3. 一行ずつ意味を説明する
1. password_hashはパスワード保存用のハッシュを生成する。
2. password_verifyは保存されたハッシュと入力パスワードの対応を検証する。
3. 認証成功時にセッションIDを更新し、個別オブジェクト操作はさらに認可する。

## 4. 頭の中で処理の流れを追う
① アカウント照合→② ハッシュ照合→③ セッションID再生成→④ 操作ごとに認可確認。

### 根本原因
漏えい時の被害が拡大し、認証と認可を取り違える。

### 修正の原理
認証は誰なのか、認可は何を許されるか。password_hashで漏えい時の平文露出リスクを減らし、ログイン後はセッション識別子を再発行する。

### 防御を重ねるとしたら
password_hash/verify、セッション管理、API単位で所有者確認、本番では試行回数制限・MFAなどを検討。
