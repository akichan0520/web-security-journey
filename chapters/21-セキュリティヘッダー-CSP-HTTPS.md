# 第21章：セキュリティヘッダー・CSP・HTTPS

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** セキュリティ

## この章でできるようになる
CSP、X-Content-Type-Options、Referrer-Policy、HTTPS/TLSの役割を説明できる。

## 全体像
安全なアプリは「入力・処理・出力」に加えて、ブラウザ動作を制約する応答ヘッダーでも守る。

## 🎙 読み上げ可能な講師ナレーション
ヘッダーはサーバーからブラウザへのルールです。CSPはスクリプトなどの読み込み元を制限します。ただしXSSの根本対策の代わりにはなりません。HTTPSは通信経路を保護しますが、ログイン後の認可ロジックまでは守りません。防御は複数層で組み合わせます。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```php
// 危険：CSPがあるから未エスケープ出力でもよいと考える
header("Content-Security-Policy: default-src 'self'");
echo $_GET['message'] ?? '';
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```php
header("Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'");
header('X-Content-Type-Options: nosniff');
echo htmlspecialchars($message, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
// HTTPS/HSTSの適用条件も別途設計
```

## 3. 一行ずつ意味を説明する
1. CSPはブラウザが参照する読み込み元の方針。
2. htmlspecialcharsはHTML本文への外部値挿入を安全にする主要対策。
3. HSTSを適用する場合はHTTPSで配信する環境とサブドメインへの影響を確認。

## 4. 頭の中で処理の流れを追う
① ブラウザがレスポンスを読む→② CSPで読み込み元などを制限→③ 正しい出力エンコードでHTML解釈を防ぐ。

### 根本原因
設定漏れや許可されたコンテキスト等に依存し、根本原因が残る。

### 修正の原理
CSPは被害低減の防御層だが、未エスケープ出力を正当化しない。TLS/HTTPS、Cookie属性、適切な出力処理を組み合わせる。

### 防御を重ねるとしたら
文脈別出力エンコード＋CSP。公開時はHTTPSとHSTSを適切に設定する。
