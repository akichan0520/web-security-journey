# 第14章：トランザクション・インデックス・マイグレーション

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** 中級

## この章でできるようになる
ACIDの意味、BEGIN/COMMIT/ROLLBACK、インデックスとクエリ計画を知る。

## 全体像
複数の更新を「全部成功か全部取り消すか」にまとめるのがトランザクション。

## 🎙 読み上げ可能な講師ナレーション
銀行の送金をイメージしてください。片方だけ引き落とし、もう片方へ入金されないと困ります。トランザクションは更新のまとまりを保ちます。インデックスは検索を速くしますが、追加更新コストと容量が増えます。変更履歴はマイグレーションで管理します。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```php
// 更新1が成功し更新2が失敗すると不一致
$pdo->exec('UPDATE accounts SET balance = balance - 10 WHERE id = 1');
$pdo->exec('UPDATE accounts SET balance = balance + 10 WHERE id = 2');
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```php
$pdo->beginTransaction();
try {
    // 実際は残高不足・並行更新なども検証する
    debitAccount($pdo, 1, 10);
    creditAccount($pdo, 2, 10);
    $pdo->commit();
} catch (Throwable $error) {
    if ($pdo->inTransaction()) $pdo->rollBack();
    throw $error;
}
```

## 3. 一行ずつ意味を説明する
1. beginTransactionは更新を一まとまりにする開始処理。
2. commitは成功した更新を確定させ、rollBackは取り消す。
3. 送金の二重実行や負残高は別問題で、競合制御・制約・冪等性などを検討。

## 4. 頭の中で処理の流れを追う
① トランザクション開始→② 出金→③ 入金→④ どちらも成功なら確定、失敗なら巻き戻す。

### 根本原因
途中失敗でデータの不整合が生じうる。

### 修正の原理
BEGINからCOMMITまでを一つの原子的な更新単位にする。これだけで残高不足や競合を防ぐわけではないため、別途ロックや整合性制約が必要。

### 防御を重ねるとしたら
関連更新はトランザクション化。外部キー、制約、適切なインデックスも併用する。
