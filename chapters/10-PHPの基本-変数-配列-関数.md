# 第10章：PHPの基本・変数・配列・関数

> **読解教材（実行不要）** — 以下のコードは比較のための断片です。危険版を実行・公開しないでください。

**難易度：** 基礎

## この章でできるようになる
PHPの実行場所、スーパーグローバル、型宣言、関数、JSON応答を理解する。

## 全体像
PHPはサーバーが処理し、HTMLやJSONを生成する。ブラウザにはPHPソースそのものは返さない。

## 🎙 読み上げ可能な講師ナレーション
PHPは受け取ったリクエストから処理を進めます。$_GETや$_POSTは利用者が指定できる値です。strict_typesで意図しない型変換を減らすことができますが、外部入力の検証は別に必要です。まずは簡単なJSONエンドポイントを追いましょう。

## 1. 危険なコードを読む
未信頼の値がどこから来て、どの命令や判断へ渡るかに注目してください。

```php
if (($_GET['role'] ?? '') === 'admin') {
    showAdminPanel();
}
```

## 2. 安全側のコードと比較する
これは設計上の考え方を伝える**抜粋**です。例外処理や周辺設定が省略されている場合があります。

```php
<?php
declare(strict_types=1);
// 認証済みIDから、サーバー側の権限を取得する
$role = getRoleForAuthenticatedUser($sessionUserId);
if ($role !== 'admin') {
    http_response_code(403);
    exit;
}
```

## 3. 一行ずつ意味を説明する
1. $_GETのroleはブラウザが自由に指定でき、役割の信頼できる根拠ではない。
2. セッション由来の主体に紐付くロールをサーバー側で参照する。
3. 403は認証済みでも許可がない処理への代表的な応答。

## 4. 頭の中で処理の流れを追う
① 入力受領→② 認証済み主体を特定→③ サーバー保持の権限を照合→④ 許可か拒否。

### 根本原因
ブラウザから送る値は改変できるため、権限の根拠にならない。

### 修正の原理
$_GETはブラウザから任意に指定できる。関数・型・配列の文法を覚えても、値の信頼境界を取り違えると権限不備になる。getRoleForAuthenticatedUserは説明用の仮関数。

### 防御を重ねるとしたら
認証済みセッションとDBの権限情報をサーバーで照合する。
