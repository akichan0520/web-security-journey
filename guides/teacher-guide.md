# 講師・レビュー担当向け進行ガイド

## 1章15〜30分の進行例

1. **導入：** 見出しと到達目標、通信の流れを説明。
2. **3分読解：** 危険な例を読み、どの値が外部入力か質問。
3. **比較：** 安全側で変わった行に注目。変更目的を一文で説明。
4. **追跡：** サンプルのデータがどの行を通るか順序をたどる。
5. **根本原因：** なぜ入力検証だけでは不十分なのか、どの境界で対策するか議論。
6. **確認：** 折りたたんだ答えを見ずに自分で説明してから答え合わせ。

## 3種類の質問

- 初心者向け：「`$keyword` はどこから来た変数ですか？」
- 中級者向け：「この処理でSQLの命令部分は変えられますか？」
- 上級者向け：「プレースホルダーを使っても残る認可上の問題はありますか？」

## 評価する観点

- **機能理解：** コードの行が何をするか説明したか。
- **入力の出所：** 未信頼データを見つけたか。
- **原因の説明：** 単に「危ない」ではなく理由を説明できるか。
- **修正の適切さ：** 元の問題の種類に対応した対策か。
- **限界の理解：** 対策が万能ではないことを説明したか。

危険なサンプルを参加者に実行させず、紙上レビューとして進めてください。
